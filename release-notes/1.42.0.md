## New Features

### Item Relations

Ìtems of type `power` and `equipment` (i.e., class/kin powers and magic items) now have a `children` system property (accessible via a new tab on those items' sheets) that lets GMs and content creators link together related items.

Related powers are grouped together in the power importer, and ticking a parent automatically ticks its children (up to the power's or actor's level). Once on the sheet, deleting a power prompts the user to also delete its children automatically as an option.

System data has already been updated to take advantage of this, so for example cleric domains and invocation powers or the various components of each monk form can now be imported and deleted as a group instead of individually.

### Power Importer Other Tab

The power importer gained a new `Other` tab where users can load content from other compendiums. Useful whenever e.g. a class element lets one borrow stuff from a different class.

The kin and class tabs now also allow users to un-select additional source compendiums if more than a single one feeds data into them (e.g. if you have a module that adds content for that class).

### List Flexible Attacks on the Chat Card

A long-requested feature, the system now has a `listFlexibles` macro, called by the relevant (newly imported) bard, fighter and druid powers, that lists and evaluates the applicability of the parent actor's flexible attacks directly on the chat card, with clickable buttons to use them from there.

One limitation: for multiclass characters with flexible attacks from both classes the macro doesn't distinguish which come from which class. If you're a bard with the `True Flexibility` feat that's actually what you'd want.

Content creators: check out how e.g. the system's fighter basic attacks call this macro to replicate this in your own custom content.

(Thanks to Martin Killmann for the original implementation of this idea.)

## Other Changes

- Retired the `roundUpDamageApplication` system setting, which was only honored in a minority of places anyway. The system now defaults to the explicit 2e ruling of ceiling the absolute value of damage or healing.

## Under the Hood

- Adjusted `ESLint` rules for the codebase, fixed indentation (now all files use tabs), line terminations (unix) and fixed the majority of ESLint warnings.
